# SOZYKIN Плагиат

Клиентская проверка курсовых и ВКР: заимствования, оформление по положению вуза,
признаки ИИ, сравнение работ группы. Статический сайт без сборки и без пакетного
менеджера, опубликован на GitHub Pages из ветки `main`. Работает в браузере и должен
открываться из России без VPN.

## Файлы сайта

| Файл | Что это |
|---|---|
| `index.html` | главная страница (стили — `site.css`) |
| `accuracy.html` | «Как работает и насколько точен» (стили — `site.css`) |
| `app.html` | само приложение: проверка работы (`#check`) и работы группы (`#group`) |
| `sw.js` | Service Worker: офлайн-режим; список страниц — в `SHELL`, при изменении набора файлов поднимать `CACHE` |
| `manifest.webmanifest`, `icons/` | установка на телефон |
| `.nojekyll` | GitHub Pages отдаёт файлы как есть, без Jekyll |

Все ссылки относительные: сайт работает по любому адресу (`…github.io/SOZYKIN-/`,
после переименования репозитория или на своём домене).

## Устройство `app.html`

| Строки (примерно) | Что там |
|---|---|
| начало | `<head>`: meta-теги, иконки и манифест файлами, скрипты с CDN (mammoth 1.8.0, pdf.js 3.11.174) |
| далее | `<style>` |
| `<script>` до конца | основной код, разбитый на разделы `// ===` с заголовками на русском |

Разделы основного скрипта по порядку: глобальное состояние `S` (сохраняется в
`localStorage` под ключами `sp_v7` / `sp_draft_v7`), тосты, словари, утилиты для
текста (`tokenize`, `escapeHtml`), детектор подозрительности документа,
MinHash + LSH, TF-IDF с косинусной мерой, чтение файлов (PDF/DOCX/TXT), локальный
анализ, метрики словаря (MTLD, HD-D, K Юла),
ИИ-провайдеры, API-режим (только оценка ИИ-генерации), поиск источников (OpenAlex,
Crossref, Semantic Scholar, arXiv, DOAJ, ru.wikipedia), извлечение поисковых запросов,
ИИ-помощник (`assistantHtml`, `askAssistant`, вход Pollinations), сравнение документа
с аннотациями источников (`findMatches`, `applySourceMatches`), точка входа анализа,
UI-хелперы, главный экран, загрузка файла,
экран прогресса, режим «Работы группы» (`renderGroup`, `runGroupComparison`), `route()`
(переключение режимов по `location.hash`), регистрация `sw.js`.

Проверка оформления DOCX (`checkDocxFormatting`, `requirementChecks`) — по
положениям БЮИ МВД России о курсовой работе (2022) и о ВКР (2023): поля, шрифт,
кегль, интервал, отступ, выравнивание, номера страниц, объём (по оглавлению) и
допустимый процент заимствований. Профили — в `WORK_TYPES`, правила — в `FORMAT_RULES`.
Структура, сноски и список литературы — `checkStructure`, `checkFootnotes`,
`checkBibliography`; строки требований из них собирает `documentRows`.

Мнение языковой модели (API-режим) в процент ИИ не входит и показывается отдельно.

ИИ-помощник (вкладка «Помощник») получает сводку отчёта, текст — только по галочке.
Подключение: свой ключ провайдера или «Войти через Pollinations» (BYOP, фрагментный
поток: ключ `sk_…` приходит в `#api_key`, проверяется `state`, хранится только
в `sessionStorage`). Своего секретного ключа у сайта нет и быть не должно; публичный
App Key `pk_…` можно вписать в `POLLINATIONS.appKey`.

ИИ-оценка по стилю (`STYLE_METRICS`, `styleScore`) — три метрики словаря (HD-D,
MTLD, K Юла) на основном тексте (`mainBodyText`), медианы по кускам в 300 слов,
откалиброваны на 9 размеченных работах (4 ИИ, 5 людей). Доля служебных слов и
запятые исключены: по открытому набору AINL-Eval 2025 это признаки жанра, а не ИИ.
Пороги вердикта — `AI_VERDICT_MIXED` / `AI_VERDICT_AI`. ИИ-клише (`AI_MARKERS`)
в оценку не входят, кроме правила-минимума при очень высокой плотности.
Сами размеченные работы в репозиторий не кладём — в них персональные данные.

Процент заимствований считается только по реальным совпадениям с текстами
источников. Повторы внутри самого документа — это «шаблонность», а не заимствование;
ИИ-модель проценты заимствований и источники не задаёт.

Найти раздел: `grep -n '^// ===' -A1 app.html`.

## Соглашения

- Без сборки: обычные HTML/CSS/JS-файлы. Не добавлять сборщик, фреймворк или `package.json` без просьбы.
- Код приложения — в `app.html`; новые страницы — отдельными HTML-файлами со `site.css`.
- Комментарии в коде пишутся по-русски и объясняют *зачем*; придерживаться этого стиля.
- Тексты интерфейса — на русском.
- Сообщения пользователю — через `toast()`, никогда не через `alert()`.
- Сначала мобильная версия: проверять при ширине телефона (390px), учитывать safe-area.
- Дизайн: чёрный фон, текст цвета слоновой кости, золото (`--gold`) — единственный акцент;
  заголовки — Cormorant Garamond, текст — Inter. Без эмодзи в интерфейсе. Токены — в `:root`
  у `app.html` и в `site.css`, держать их одинаковыми. Шапка должна помещаться в 360px.

## Правила безопасности (по мотивам `rules/security.md` из everything-claude-code)

- Никогда не коммитить API-ключи. Ключ пользователя хранится только в `S.apiKey` /
  `localStorage` и отправляется только на адрес выбранного провайдера.
- Всё, что приходит из документа, из ответа API или от пользователя и попадает в
  `innerHTML` или в шаблонную строку с HTML, должно проходить через `escapeHtml()`.
- Внешние скрипты: только с cdnjs и с точно указанной версией.
- Новые сетевые запросы: только HTTPS и корректная работа, если сервис недоступен
  (работа без VPN — обязательное требование).

## Порядок работы

- Перед крупными изменениями — `/plan` (использует агента `planner`).
- После изменений — `/verify` (или напрямую `node .claude/scripts/verify.mjs`).
  Скрипт проверяет синтаксис встроенных скриптов всех страниц, `sw.js` и манифест,
  а если установлен Playwright — открывает каждую страницу в headless Chromium
  и ловит ошибки и горизонтальную прокрутку на 390px.
- Готовые изменения проверять агентом `code-reviewer`; при работе с API-ключами,
  разбором файлов или `innerHTML` — агентом `security-reviewer` или навыком
  `security-review`.
- Сообщения коммитов: `<тип>: <описание>`, типы: feat, fix, refactor, docs, test,
  chore, perf, ci.

## Настройка Claude Code

В `.claude/` лежит часть набора
[everything-claude-code](https://github.com/worldflowai/everything-claude-code)
(лицензия MIT, автор Affaan Mustafa), отобранная для статического сайта и переведённая
на русский:

- `agents/`: planner, architect, code-reviewer, security-reviewer
- `skills/security-review`
- `commands/`: `/plan`, `/learn`, `/checkpoint` (слегка адаптированы), `/verify` (переписана под этот репозиторий)
- `scripts/verify.mjs`: проверки, которые запускает `/verify`

Намеренно не перенесены: TDD и требования к покрытию тестами, агенты для ошибок
сборки и E2E-тестов, навыки для React, бэкенда и ClickHouse, а также исходные хуки
(tmux, Prettier, tsc, запрет `.md`-файлов) — они рассчитаны на проекты на
Node/TypeScript.
